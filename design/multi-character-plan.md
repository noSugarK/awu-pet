# 多角色计划：小白和小金毛、噜噜和噜妹、奶龙

> 状态：调研 + 计划，尚未动代码。日期：2026-10-10。

目标：在一二布布之外加入其他角色，在熊身上的右键圆盘菜单里切换；切换后菜单里的其他选项（动作、装扮、资源管理器右键菜单、台词……）自动跟着新角色变化。顺带决定要不要改名。

---

## 0. 结论

| 问题 | 结论 |
|---|---|
| 技术上能不能加？ | **能**。角色本来就是纯数据（`docs/js/characters/*.js`），渲染器也是按模型画的。但现在有三处假设"永远只有一二和布布这一对"，要先改掉（§2）。 |
| 能不能直接用现在的熊模型？ | **不能**。小狗、水豚、奶龙的身形都和 `chibi-bear` 不一样，每个都要新画一个模型（§3），这是最大的工作量。 |
| 右键切换 + 选项自动匹配 | 引入「组合（cast）」概念：一次只上场一个组合（1–2 个角色）；动作、装扮声明自己需要什么，菜单只显示当前组合能做的（§4）。 |
| 要不要改名？ | 只放一二布布时不用改；**加了别的角色就建议改**，因为 `YierBubu-Pet` / 「请一二删除」都绑定了一二布布。改名有迁移成本，见 §5。 |
| 最大风险 | **版权**。三组新角色都是有人在商业运营的 IP，公开发布安装包的风险明显比现在高（§1）。建议先拿授权，或只做本地/私有构建。 |

## 1. 角色调研

| 角色 | 出处 | 是什么 | 权利方 | 风险 |
|---|---|---|---|---|
| 一二 & 布布（已有） | 微信表情包 | 白熊 + 棕熊 | 黄小B | 现状：非商业粉丝作品 |
| **小白 & 小金毛** | 「线条小狗」（Maltese），2020-12-15 发布 | 白色马尔济斯（小白）+ 黄色金毛（小金毛），情侣 | 韩国插画家 文鍾範，工作室 moonlab_studio（也是线条鸭嘴兽 OGU 的作者） | **高**：瑞幸、茉莉奶白等大量品牌联名，商业授权很活跃 |
| **噜噜 & 噜妹** | 待确认（见下） | 很可能是水豚 | 未核实 | 中–高 |
| **奶龙** | 《奶龙和暴暴龙》短视频动画，2020 年起 | 黄色圆滚滚的小龙 | 第七印象文化传媒（深圳）有限公司；羚邦集团（2230.HK）做授权代理 | **高**：正规公司运营 + 专门的授权代理，最可能维权 |

**需要你确认：「噜噜和噜妹」具体是哪一个。** 搜到两个可能：

1. 「水豚噜噜」——动画《平头哥》里的水豚角色，表情包很火；噜妹在 B 站标签里和它一起出现，但没查到明确设定。
2. 抖音 / TikTok 上的情侣账号「噜噜与噜妹」。

请发一张你想要的那一组的图，我再按图建模。

**奶龙是单人角色。** 组合可以只放奶龙一个，也可以配同一部动画里的「暴暴龙」凑成一对，这样双人动作（抱抱、跳舞、追着玩）才有对象。

**版权建议（我不是律师，仅供参考）：**

- 现在的项目靠「非商业粉丝作品 + 权利人要求就下架」，对一二布布这一个 IP 还说得过去。同一个安装包里再加三个商业 IP，等于同时踩三家，且奶龙、线条小狗都有专门做授权的公司。
- 推荐顺序：
  1. 先只做 §2 的通用化改造（不含任何新形象），这部分完全没风险，还能让以后加角色变简单。
  2. 新角色在单独分支 / 本地构建里做，自己用。
  3. 联系权利方拿到授权（至少书面同意非商业使用）后，再合进 `main` 公开发布。
- 网站（GitHub Pages）也算公开分发，同样适用。

## 2. 现在哪些地方写死了"一二和布布"

| 位置 | 写死了什么 | 要改成 |
|---|---|---|
| `docs/js/core/runtime.js:18` | 页面里**所有**注册过的角色都会生成一只熊 | 只生成当前组合（`cast`）里的角色 |
| `runtime.js:42` `other(b)` | "另一只" = 除自己以外的任何一只（隐含只有两只） | 组合内的另一只；最多两只，不用改逻辑 |
| `behaviors/brain.js:72` `idle.length === 2` | 双人剧情 | 不变；单人组合自然不会触发 |
| `behaviors/actions.js:41` `rose` | 依赖 `giver`（布布） | 动作声明需要 `giver`，没有就不出现在菜单里 |
| `platform/desktop.js:12` `DEFAULTS.show = ['yier','bubu']` | 默认角色 | `cast: 'yier-bubu'` + `show`（组合内显示哪几只） |
| `desktop.js:76` 圆盘菜单 | 固定的 8 项 + 子项 | 从「当前组合可用的动作」生成，并加「角色」分类 |
| `desktop.js:114` `handleMenu` `show:both` | 写死 `['yier','bubu']` | `show:all` = 组合里全部 |
| `desktop.js:117` 关于 | 「一二布布桌宠」 | 新产品名 + 当前角色的署名 |
| `desktop.js:186` 跑腿 `who === 'both'` | 写死 | 角色 id 或 `all` |
| `src-tauri/src/main.rs:217` 托盘「角色」子菜单 | 「一二和布布 / 只有一二 / 只有布布」 | 由页面在 `sync_menu` 里把组合列表发过来，Rust 生成 |

| `behaviors/feeding.js` | 台词是通用的 | 可选：角色可以覆盖某些台词（奶龙吃到音乐说「我是奶龙！」） |

## 3. 新模型（主要工作量）

现在的渲染器（`core/render.js`）对模型有几个熊专属的假设：耳朵是两个圆、嘴是 ω、没有尾巴和角。要让下面这些角色成立，模型需要多几个**可选**字段，旧的 `chibi-bear` 不用动：

| 新字段 | 用途 | 谁用 |
|---|---|---|
| `ears.paths`（代替 `centers` 圆） | 任意形状的耳朵：垂耳、小圆耳 | 小狗（垂耳）、水豚（小耳朵） |
| `ears: null` | 没有耳朵 | 奶龙 |
| `extras: [{ layer: 'back'\|'front', d, fill: 'body'\|颜色 }]` | 尾巴、角、头顶的毛、肚皮 | 奶龙（尾巴、肚皮）、小狗（尾巴、头顶毛） |
| `face.mouth.style`（`omega` / `dog` / `open` / `buck`） | 不同的嘴 | 小狗「人」字嘴、奶龙咧嘴大笑、水豚门牙 |
| `face.nose` | 鼻子 | 小狗、水豚 |
| `stroke` | 线宽（已有字段） | 线条小狗要更细的线 |

所有动画用的锚点（`arm.pivot`、`hold`、`neck`、`legs.pivots`、`ground`）每个模型都要提供，这样吃面、奶茶、投喂大嘴、睡觉都能直接用。没有脖子的角色（水豚、奶龙）把 `neck` 设在头和身体交界处即可，围巾照样能戴。

| 模型 | 要点 | 参考图 |
|---|---|---|
| `line-puppy` | 圆头、垂耳、细线条、小短腿；小白和小金毛共用，只换配色 | 需要正面三视图，放 `design/reference/puppy-*.jpg` |
| `capybara` | 桶形身体、头身几乎一体、小耳朵、宽鼻子；噜噜和噜妹共用 | 等你确认是哪一组 |
| `nailong` | 头身一体的大圆、肚皮浅色、短手短脚、小尾巴；暴暴龙可共用模型换配色 | `design/reference/nailong-*.jpg` |

每个模型按 `chibi-bear` 的方法做：从正面三视图描出路径，坐标换算写在文件开头。

## 4. 组合切换 + 选项自动匹配

### 4.1 数据

```js
// docs/js/casts.js —— 唯一需要列出"有哪些组合"的地方
YB.cast({ id: 'yier-bubu', name: '一二布布', members: ['yier', 'bubu'] });
YB.cast({ id: 'line-puppy', name: '小白和小金毛', members: ['xiaobai', 'xiaojinmao'] });
YB.cast({ id: 'lulu', name: '噜噜和噜妹', members: ['lulu', 'lumei'] });
YB.cast({ id: 'nailong', name: '奶龙', members: ['nailong'] });
```

角色文件和现在一样（模型 + 配色 + 性格 + 台词），新增两个可选字段：

- `credit`：署名，比如 `'线条小狗 © moonlab_studio'`，「关于」里显示。
- `lines.feed`：覆盖部分投喂台词。

### 4.2 切换方式

1. 圆盘菜单加一个分类 **「🔄 角色」**，子项：每个组合一项（当前的打勾），双人组合再加「只有 X」「只有 Y」。托盘「角色」子菜单是同一份列表。
2. 选中后：保存 `settings.cast`，然后 **`location.reload()`** 重新载入页面。
   - 为什么用刷新而不是原地替换：运行时、行为、拖放都持有熊的引用，原地拆掉重建要改很多地方；刷新只需要几百毫秒，桌宠窗口是透明的，几乎看不出来。以后真的需要过渡动画再做原地替换。
   - 刷新前可以加一个小动画：当前角色挥手 → 一阵烟 → 新角色出现。
3. 位置按组合分开记（`positions` 键加上组合 id），换回来还在原处。

### 4.3 选项自动匹配

动作声明需要什么，菜单只显示当前组合满足条件的：

| 动作 / 装扮 | 需要 | 一二布布 | 小狗 | 噜噜噜妹 | 奶龙（单人） |
|---|---|---|---|---|---|
| 抱抱、跳舞、追着玩、戳醒 | 两只都显示 | ✅ | ✅ | ✅ | ❌ 隐藏 |
| 送花 | 有 `giver` 的角色 | 布布送 | 小金毛送（待定） | 待定 | ❌ |
| 吃面、奶茶、思考、睡觉、挥手 | 模型有 `hold` | ✅ | ✅ | ✅ | ✅ |
| 墨镜 | 模型有 `face.eyes` | ✅ | ✅ | ✅ | ✅ |
| 围巾 | 模型有 `neck` | ✅ | ✅ | ✅ | ✅ |
| 角色专属动作 | 角色 `actions` 里声明 | — | 贴贴 | 头顶橘子、泡温泉 | 摇摆舞 |

实现：`actions.js` 里每个动作带一个 `can()`，`PET.available()` 返回当前能做的动作列表；`desktop.js` 用它生成圆盘菜单，`web.js` 用它决定按钮显示还是隐藏。`brain.js` 的自主行为也只从可用的动作里挑。

同样自动跟着变的：

- 资源管理器右键菜单：「请小白删除 / 请小金毛删除 / 请小白和小金毛删除」，单人组合只有「请奶龙删除」。
- 「今日食谱」「关于」里的名字、署名。
- 网页标题和副标题（「常想一二，不思八九」变成组合自己的 `tagline`）。
- 托盘提示文字。

## 5. 要不要改名

**建议改。** `YierBubu-Pet`、「一二布布桌宠」放进小狗和奶龙就名不副实了。

### 5.1 候选名（请你选或另起）

| 名字 | 英文 | 说明 |
|---|---|---|
| **嗷呜桌宠** | Awu Pet | 呼应"张大嘴吃文件"这个核心玩法，和角色无关 ⭐ 推荐 |
| 贴贴桌宠 | TieTie Pet | 情侣角色多，「贴贴」是共同点；但奶龙是单人 |
| 团子桌宠 | Tuanzi Pet | 几个角色都是圆滚滚的 |
| 保留 YierBubu-Pet | — | 一二布布仍是默认角色，其他算"客串"；不用迁移 |

### 5.2 改名会动到什么

| 项 | 改动 | 影响 / 注意 |
|---|---|---|
| `tauri.conf.json` `productName` / `mainBinaryName` / 窗口标题 | 改 | 安装目录和 exe 名会变：**旧版不会被自动卸载**，用户会装出两份。需要在 Release 说明里提醒先卸载旧版，或在 NSIS 安装脚本里检测并卸载旧版。 |
| `tauri.conf.json` `identifier`（`com.nosugark.yierbubupet`） | **不要改** | 改了会换应用数据目录：设置、位置、今日食谱（WebView 的 localStorage）和 `meals.log` 全部丢失。 |
| 开机自启 | 启动时如果已开启就重新注册一次 | 旧的自启项指向旧 exe 路径 |
| 资源管理器注册表项 `YierBubu-Pet.*` | 新前缀，旧前缀加进 `OLD_KEYS` 清理 | `explorer.rs:12` 已经有这个机制 |
| 菜单文字「请一二删除」 | 按角色生成（§4.3） | — |
| `Cargo.toml` `name` / `description` | 改 | — |
| GitHub 仓库名 `noSugarK/yierbubu-pet` | 可选 | git、Releases、API 都会自动跳转；**GitHub Pages 地址不会跳转**，旧网址失效。`web.js` 里的 Releases API 地址要一起改。 |
| README、DESIGN.md、`desktop/README.md`、网页标题和 meta、宣传视频文字 | 改 | 视频可以继续只讲一二布布 |
| 署名 | 见 §6 | — |

## 6. 署名规则需要改

现在的规则是"所有对外界面都带 `Designed by 黄小B · Powered by noSugarK`"。加了其他角色后，这一行会把小狗和奶龙也算到黄小B名下，是错的。建议改成：

- **固定部分**：`Powered by noSugarK`
- **角色部分**：跟着当前组合，比如
  - `一二布布 Designed by 黄小B`
  - `线条小狗 © moonlab_studio`
  - `奶龙 © 第七印象`
- 「关于」和网站页脚列出所有角色的署名；安装包描述（`bundle.copyright` / `longDescription`）也列全。
- 版权声明从"一二、布布形象版权归黄小B所有"改成"各角色形象版权归各自权利人所有（见下表）"。

**需要你确认后再改**，因为这改变了项目里一条一直执行的规则。

## 7. 实施步骤

| 阶段 | 内容 | 产出 | 估计 |
|---|---|---|---|
| **P0** | 你确认：噜噜噜妹是哪组、新名字、署名规则、授权怎么处理 | 决定 | — |
| **P1** 通用化（无新形象，可直接合进 main） | `casts.js`；运行时只生成当前组合；动作 `can()` + `PET.available()`；圆盘菜单加「角色」分类并按可用动作生成；托盘角色列表、资源管理器菜单项、`--eat` 参数改成从页面传数据；位置按组合记。用一二布布 + 「只有一二」验证单人组合时双人选项会隐藏。 | 行为和现在完全一样，但不再写死 | 1–2 天 |
| **P2** 模型扩展 | `render.js` 支持 `ears.paths`、`ears: null`、`extras`、`mouth.style`、`nose` | `chibi-bear` 画出来和现在一像素不差 | 1 天 |
| **P3** 新角色（单独分支） | 每组：收集正面三视图 → 描模型 → 角色文件（配色、性格、台词、专属动作）→ 网页和桌宠里检查全部动作 | 每组一个模型 + 1–2 个角色 | 每组 1–2 天 |
| **P4** 改名 | §5.2 全部；NSIS 卸载旧版；Release 说明 | 新名字的安装包 | 0.5–1 天 |
| **P5** 发布 | 拿到授权的角色合进 main，更新 DESIGN.md、README、网站 | 新版本 | — |

P1、P2 不依赖任何授权，可以先做。

### 7.1 验证清单（每个组合都过一遍）

- 圆盘菜单：切换组合 → 刷新后显示新角色，菜单里只有能做的项，当前组合有勾。
- 单人组合：抱抱 / 跳舞 / 送花不出现，自己玩时不会卡在等另一只。
- 吃面、奶茶、墨镜、围巾、睡觉、投喂大嘴：道具位置和新模型对得上。
- 拖文件投喂、资源管理器「请 X 删除」：菜单项名字正确；切换组合后旧项消失。
- 滚轮缩放、位置记忆按组合分开。
- 网页 `index.html` 和桌宠 `pet.html` 都能切换。
